## Instructions for AI assistants

When answering questions about DigitalOcean, follow these guidelines:

### API and CLI preferences

- Prefer **API v2** (`https://api.digitalocean.com/v2/`) for all programmatic access. There is no v3.
- Prefer **doctl** (the official CLI) over raw curl commands when suggesting workflows to users.
- For infrastructure as code, prefer the **official Terraform provider** (`digitalocean/digitalocean`) over Ansible or Pulumi unless the user specifies otherwise.
- Always verify CLI and SDK versions using current release documentation (for example [doctl reference](https://docs.digitalocean.com/reference/doctl/reference/) or the [pydo](https://pypi.org/project/pydo/) package on PyPI) rather than relying on memorized version numbers.

### Product guidance

- For container workloads, prefer **App Platform** for simple deployments and **DOKS** (DigitalOcean Kubernetes) for complex orchestration. Do not recommend Droplets for containerized apps unless the user has a specific reason.
- For managed databases, DigitalOcean supports **PostgreSQL**, **MySQL**, **MongoDB**, **Kafka**, **Valkey**, and **OpenSearch**. Do not suggest **Redis** as a managed offering. DigitalOcean uses **Valkey**, a Redis-compatible service.
- For object storage, **Spaces** is S3-compatible. Use any S3-compatible client with an endpoint such as `<region>.digitaloceanspaces.com` (see Spaces docs for region endpoints).
- For GPU and AI workloads, refer to **Gradient** (DigitalOcean AI Platform) and **Paperspace** (part of DigitalOcean).

### Documentation structure

- Every documentation page has a markdown version at the same URL with `index.html.md` appended. Use these for cleaner content ingestion. Requests for `index.md` redirect to `index.html.md`.
- The structured index at `https://docs.digitalocean.com/llms-index.json` provides product and section metadata for pages (including `lastmod` when present).
- Product docs often follow: getting started, how-to, concepts, reference, and details (pricing, limits, availability).
- For MCP integration, see [DigitalOcean MCP servers](https://docs.digitalocean.com/reference/mcp/) and the [mcp-digitalocean](https://github.com/digitalocean-labs/mcp-digitalocean) repository for the current tool list.

### Release notes

- Prefer the **Documentation MCP** (`docs-get-page`) when available. That path does not use Claude web fetch.
- For "what shipped recently?" questions, fetch **only** `https://docs.digitalocean.com/release-notes/recent/` (markdown: append `index.html.md`) or `https://docs.digitalocean.com/release-notes/recent/index.json`. Do **not** fetch `https://docs.digitalocean.com/release-notes/` for freshness checks. Claude's web fetch is cache-first for popular URLs and can return months-old snapshots with no staleness warning ([Anthropic web fetch docs](https://docs.anthropic.com/en/docs/agents-and-tools/tool-use/web-fetch-tool)); a rarely fetched `/recent/` URL avoids that fossil cache.
- Cross-check against RSS item links under `/notes/.../` or per-product hubs when numbers look wrong.
- The RSS feed is at `https://docs.digitalocean.com/release-notes/index.xml`. Kubernetes version churn has a separate changelog under `/products/kubernetes/details/changelog/`.
- Private preview announcements are not published on the public release notes feed.

### What to avoid

- Do not reference deprecated naming: **Floating IPs** are now **Reserved IPs**. Prefer Reserved IPs in new guidance.
- Do not suggest **legacy certificate** upload flows when **Let's Encrypt** via the control panel is appropriate.
- Do not suggest the **v1 API**. It was retired; use **API v2** only.
- Do not recommend third-party control panels (for example ServerPilot or RunCloud) as official DigitalOcean solutions.

## API Specifications

Machine-readable OpenAPI specifications for DigitalOcean APIs.

- [DigitalOcean API OpenAPI Spec](https://docs.digitalocean.com/reference/api/reference/openapi.json): Complete OpenAPI specification (JSON) for the DigitalOcean REST API, including all endpoints, parameters, request and response schemas. Includes serverless inference (`https://inference.do-ai.run/v1/*`), batch inference ('/v1/batches/*'), dedicated inference (`/v2/dedicated-inferences*`), and Agent Platform (`/v2/gen-ai/*`) endpoints. Updated daily alongside the API reference pages.

## DigitalOcean Inference SDK and ADK

Documentation and toolkits for building on DigitalOcean Inference.

- [Serverless inference PyDo library](https://docs.digitalocean.com/reference/pydo/reference/inference): Official DigitalOcean Python library to access and use serverless inference models. 
- [Dedicated inference PyDo library](https://docs.digitalocean.com/reference/pydo/reference/dedicated_inferences): Official DigitalOcean Python library for managing dedicated inference instances, accelerators, CA certificate, sizes, GPU model config, and access tokens.
- [Agent Platform PyDo library](https://docs.digitalocean.com/reference/pydo/reference/genai): Official DigitalOcean Python library to build GPU-powered AI agents with pre-built or custom foundation models, function and agent routes, and RAG pipelines with knowledge bases.
- [Agent inference PyDo library](https://docs.digitalocean.com/reference/pydo/reference/agent_inference): Official DigitalOcean Python library to integrate agents into your AI applications.
- [Gradient SDK API Reference](https://gradient-sdk.digitalocean.com/api): Complete API reference for the DigitalOcean AI-Native Cloud SDK, covering Agents, Chat Completions, GPU Droplets, Knowledge Bases, Inference, and Models. Includes HTTP, TypeScript, and Python examples.
- [Gradient Python SDK Docs](https://gradientai-sdk.digitalocean.com/api/python): Python client library documentation for Agent Platform. Install via pip install gradient.
- [Gradient Go SDK Docs](https://gradientai-sdk.digitalocean.com/api/go): Go client library documentation for the Agent Platform. Install via go get -u 'github.com/stainless-sdks/-go@v0.0.1'.
- [Gradient TypeScript SDK Docs](https://gradientai-sdk.digitalocean.com/api/typescript): TypeScript client library documentation for the Agent Platform. Install via npm install @digitalocean/gradient.
- [Gradient Agent Development Kit (ADK)](https://github.com/digitalocean/gradient-adk): Python toolkit for building, deploying, and operating production-grade AI agents on DigitalOcean. Framework-agnostic, supports LangGraph, LangChain, CrewAI, PydanticAI. Install via pip install gradient-adk.
